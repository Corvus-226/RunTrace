# RunTrace v0.1.0

Published on 2026-08-13 through PyPI Trusted Publishing. The package is
available from [PyPI](https://pypi.org/project/ml-runtrace/0.1.0/), and the
corresponding [GitHub Release](https://github.com/Corvus-226/RunTrace/releases/tag/v0.1.0)
points to the reviewed `v0.1.0` tag.

RunTrace v0.1.0 is the first public release of a lightweight, local-first CLI
for recording and comparing machine-learning experiment context.

## Highlights

- Capture Git commit, branch, detached state, and dirty state.
- Capture Python, operating-system, architecture, installed distribution, and
  optional NVIDIA GPU/CUDA metadata.
- Store validated, human-readable YAML snapshots under `.runtrace/runs/`.
- Record optional experiment names, commands, and repository-local YAML config
  paths, hashes, and parsed values.
- List runs, show complete historical records, and compare two runs by full or
  unique abbreviated IDs.
- Recursively compare configuration mappings and arrays alongside Git,
  runtime, platform, and dependency changes.
- Run locally without an account, server, database, or automatic upload.

## Install

Install the `ml-runtrace` distribution from PyPI, then use the approved
`ml-runtrace` command or `ml_runtrace` Python module:

```console
python -m pip install ml-runtrace==0.1.0
ml-runtrace --version
python -m ml_runtrace --version
```

RunTrace v0.1.0 supports Python 3.10, 3.11, and 3.12.

## First workflow

From a Git repository with at least one commit:

```console
ml-runtrace init
ml-runtrace snapshot --name baseline --config configs/train.yaml --command "python train.py --config configs/train.yaml"
ml-runtrace list
ml-runtrace show <run-id>
ml-runtrace diff <baseline-id> <candidate-id>
```

See the
[Getting Started guide](https://github.com/Corvus-226/RunTrace/blob/v0.1.0/docs/getting-started.md)
for a complete walkthrough.

## Privacy

RunTrace does not upload source, experiment data, credentials, environment
variables, or artifacts. Values explicitly supplied through `--config` and
`--command` are persisted in local snapshot YAML and should be reviewed before
sharing.

## Known limits

- RunTrace records reproducibility context; it does not track metrics, host a
  dashboard, schedule jobs, or store model artifacts.
- GPU and CUDA detection is best-effort and currently targets NVIDIA tooling.
- Snapshot schema version 1 and the CLI may evolve during the 0.x series.
- Stored snapshots are local files; teams choose whether to ignore, archive,
  or review and commit them.
