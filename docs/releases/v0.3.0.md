# RunTrace v0.3.0

Release materials prepared on 2026-08-20 for the existing protected PyPI
Trusted Publishing workflow. Check the versioned
[PyPI project](https://pypi.org/project/ml-runtrace/) and
[GitHub Releases](https://github.com/Corvus-226/RunTrace/releases) pages for
the authoritative publication state.

RunTrace v0.3.0 adds a small, explicit bridge between local reproducibility
records and external logs, metrics, and traces: the wrapped experiment process
receives the exact saved RunTrace ID as `RUNTRACE_RUN_ID`.

## Highlights

- `ml-runtrace run` saves the snapshot before exposing its ID to the child
  process as `RUNTRACE_RUN_ID=<12-character-id>`.
- The child and ordinary descendants can attach that value to a structured log,
  metric label, observability resource, or span as `runtrace.run.id`.
- A stale inherited `RUNTRACE_RUN_ID` is replaced for the wrapped command while
  the parent process environment remains unchanged.
- The new run-correlation guide includes dependency-free JSON logging and
  optional OpenTelemetry examples.
- RunTrace remains local-first: it does not create spans, add an observability
  dependency, configure an exporter, rewrite `OTEL_RESOURCE_ATTRIBUTES`, or
  send telemetry.

## Install or upgrade

Install the collision-free `ml-runtrace` distribution and use its
`ml-runtrace` command or `ml_runtrace` Python module:

```console
python -m pip install --upgrade ml-runtrace==0.3.0
ml-runtrace --version
python -m ml_runtrace --version
```

RunTrace v0.3.0 supports Python 3.10, 3.11, and 3.12 on Windows and Linux.

## Correlate an experiment

From an initialized Git repository with at least one commit:

```console
ml-runtrace run --name baseline -- python train.py
```

Representative output includes the saved identifier and the child contract:

```text
Created snapshot a31f82000001.
Child environment: RUNTRACE_RUN_ID=a31f82000001
```

Application code that already uses OpenTelemetry can attach the value without
RunTrace knowing about the SDK or exporter:

```python
import os

from opentelemetry import trace

run_id = os.environ.get("RUNTRACE_RUN_ID")
if run_id is not None:
    trace.get_current_span().set_attribute("runtrace.run.id", run_id)
```

Later, copy that attribute from the observed event and inspect its local
provenance with `ml-runtrace show <run-id>`.

## Compatibility and privacy

- Snapshot schema v1 is unchanged. Existing v0.1.0 and v0.2.0 snapshots load
  without migration.
- `init`, manual `snapshot`, `list`, `show`, and `diff` behavior is unchanged.
- The v0.2.0 exact-argv, no-implicit-shell, snapshot-failure, child-failure, and
  exit-code contracts remain intact.
- The distribution remains `ml-runtrace`, the import remains `ml_runtrace`, and
  the only console command remains `ml-runtrace`.
- RunTrace injects only its generated identifier and does not read or persist
  the inherited environment. The ID reaches an external backend only when the
  application or its independently configured instrumentation sends it.

## Known limits

- Local descendants normally inherit the ID. Remote workers, containers,
  schedulers, and environment-sanitizing launchers must forward it explicitly.
- `runtrace.run.id` is a RunTrace-specific attribute rather than an
  OpenTelemetry semantic convention.
- RunTrace records reproducibility context; it does not track metrics, host a
  dashboard, schedule jobs, or store model artifacts.
- Stored snapshots remain local YAML files; teams choose whether to ignore,
  archive, or review and commit them.
